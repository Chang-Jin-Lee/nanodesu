# Contributing to nanodesu 🐰

First off — **welcome!** If you love anime, manga, or games, you belong here. This project exists for people who get excited when their favorite series trends, and every kind of contribution counts: you don't need to write a single line of code to make nanodesu better.

## 💜 Ways to contribute

**No code needed:**
- **Add titles to the watchlist** — know a series we're not tracking? Add it to `config/watchlist.yaml` with its `canonical` name, `category` (`anime` or `game`), and `aliases`. Japanese aliases are especially valuable — they're how we catch mentions in Japanese news.
- **Fix aliases** — if a title is being missed because a common romanization or Japanese spelling isn't listed, adding one alias directly improves the rankings.
- **Suggest a news source** — a good anime/game news site or feed we should track? [Open an issue](../../issues) and tell us about it.
- **Report bugs** — wrong category, a broken table, a title matching the wrong articles? Open an issue with what you saw and what you expected.
- **Share ideas** — new report sections, new regions, better ranking signals. Ideas are contributions too.

**Code contributions:**
- **Add a fetcher** — RSS sources only need an entry in `config/sources.yaml` (`slug`, `type: rss`, `region`, `url`). Scraped sources get a module under `scripts/fetch/` with tests and fixtures.
- **Improve the pipeline** — matching accuracy, ranking logic, report rendering. The flow is `fetch_all → sync_watchlist → extract_mentions → rank_trends → build_events → render_reports`, one module per step under `scripts/`.

## 🛠️ Development setup

```bash
git clone https://github.com/Chang-Jin-Lee/nanodesu.git
cd nanodesu
python -m venv .venv
# Windows: .venv\Scripts\activate   macOS/Linux: source .venv/bin/activate
pip install -r requirements-dev.txt
python -m pytest
```

All tests should pass on a fresh clone. If they don't, that's a bug — please report it!

## 📬 Pull request process

1. **Fork** the repo and create a branch from `master` (`git checkout -b add-frieren-aliases`).
2. **Keep it focused** — one change per PR. Small PRs get reviewed fast; giant ones stall.
3. **Add or update tests** for anything you change in `scripts/`. Every module has a matching `tests/test_*.py` file.
4. **Run `python -m pytest`** and make sure everything passes.
5. **Don't hand-edit generated files** — `data/`, `reports/`, and the README's marker sections are regenerated by the GitHub Actions pipeline and will be overwritten.
6. **Open the PR** with a short description of what changed and why. Screenshots welcome for report-format changes.

We aim to respond to PRs and issues within a few days. If yours slips through, a friendly ping is always okay.

## 🌏 Language

English is preferred for code, comments, issues, and PRs so that everyone can participate — but don't let language stop you. Japanese and Korean issues are fine; we'll figure it out together.

## 🕊️ Be kind

Be welcoming, be patient, assume good intent. Fans arguing about which series is best-girl material: encouraged. Being rude to other contributors: not.

## 🤝 Scraping etiquette

When adding sources, respect the site's terms of service and robots.txt, and set a `crawl_delay` if the site requests one. We only store titles, dates, and links — never full article content.
